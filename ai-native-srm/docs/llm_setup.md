# Подключение LLM: любая API-модель, GigaChat, YandexGPT, локальные веса

Движок работает на пяти провайдерах и **никогда не остаётся без ответа**:

```
Any API (OpenAI-совместимый чат) → GigaChat → YandexGPT → Local (своя модель) → Mock
```

Первый провайдер — универсальный: подойдёт любая модель с API в формате OpenAI
(OpenRouter, DeepSeek, Groq, Qwen, Mistral, OpenAI, Together, внутренний шлюз), включается тремя
переменными и не требует правки кода. GigaChat и YandexGPT остаются в цепочке для случаев,
когда по 152-ФЗ модель обязана быть в РФ. Чтобы оставить ровно одну модель, укажите
`LLM_PROVIDER=api,mock` — mock всё равно замыкает цепочку.

Облачные модели формулируют текст, но не принимают решений: категория, маршрут и числа
считаются кодом (`core/tools.py`, Policy Matrix), а модель лишь переписывает факты в ответ.
Если облако не ответило за отведённый бюджет времени или вернуло ошибку, цепочка молча уходит
к следующему провайдеру — клиент в любом случае получит ответ. Поэтому подключать LLM можно
и нужно «постепенно»: с пустыми ключами система полностью работоспособна на mock.

## 1. Что задать в `.env`

Минимум для облака — три строки: `LLM_PROVIDER` и ключи нужного провайдера.

```dotenv
# auto — провайдеры с ключами по порядку (api → gigachat → yandex → local), затем mock.
# Явный список задаёт порядок: api,mock | gigachat,api | yandex,gigachat — как удобно.
LLM_PROVIDER=auto
LLM_TIMEOUT_S=2.5          # бюджет времени на один вызов модели
```

### Любая API-модель (проще всего)

Провайдер `api` говорит на OpenAI-совместимом протоколе (`POST /chat/completions`), поэтому
вендор не важен — важны три значения. Сменили модель — поменяли строку в `.env`, код не трогали.

```dotenv
LLM_API_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=<ключ провайдера>          # у шлюзов без авторизации можно оставить пустым
LLM_API_MODEL=gpt-4o-mini              # имя модели у провайдера
LLM_API_MAX_TOKENS=800
LLM_JSON_MODE=false                    # true — просить строгий JSON (нужен не всем шлюзам)
```

Привычные имена тоже читаются: `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`
(используются, только если не заданы `LLM_API_*`).

| Провайдер | `LLM_API_BASE_URL` | Пример `LLM_API_MODEL` |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini`, `gpt-4.1-mini` |
| OpenRouter (сотни моделей, один ключ) | `https://openrouter.ai/api/v1` | `anthropic/claude-3.5-sonnet`, `qwen/qwen-2.5-72b-instruct` |
| DeepSeek (дешёвый, сильный в коде) | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Groq (очень быстрый инференс) | `https://api.groq.com/openai/v1` | `llama-3.3-70b-versatile` |
| Qwen / DashScope | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| Mistral | `https://api.mistral.ai/v1` | `mistral-small-latest` |
| Together | `https://api.together.xyz/v1` | `meta-llama/Llama-3.3-70B-Instruct-Turbo` |
| Свой шлюз / прокси | `http://llm-gateway.internal/v1` | как называется модель внутри |

Проверка: `python scripts/llm_check.py --provider api` — тот же скрипт, что и для остальных
провайдеров: два вызова (JSON и текст), задержка и подсказка при ошибке (401/402/403/404/429).

Названия-синонимы в `LLM_PROVIDER` (`openai`, `openrouter`, `deepseek`, `groq`, `qwen`, `mistral`,
`together`, `vllm`) указывают на тот же провайдер `api` — удобно писать
`LLM_PROVIDER=openrouter,local`, когда хочется зафиксировать порядок.

Что уходит в облако: как и у любого внешнего провайдера — только маскированный текст
(`core/masking.py`), персональные данные остаются в контуре CRM. Если модель обязана быть
в РФ — ставьте `LLM_PROVIDER=gigachat,api` (GigaChat первым) или `LLM_PROVIDER=local`.

### Где взять бесплатную модель (для демо и портфолио)

Платить на старте не нужно: у нескольких провайдеров есть постоянный бесплатный тариф без
карты. Все они говорят на OpenAI-совместимом протоколе, то есть подключаются теми же
`LLM_API_*` — меняется только адрес, ключ и имя модели.

| Провайдер | Бесплатно | Где взять ключ | Куда вписать адрес |
|---|---|---|---|
| **Groq** — быстрее всех, лимиты щедрее | 30 запросов/мин, 1 000/сутки, 200 000 токенов/сутки на `openai/gpt-oss-120b` (без карты) | console.groq.com/keys | `https://api.groq.com/openai/v1` |
| **OpenRouter** — один ключ, много моделей | 20 запросов/мин, 50/сутки (1 000/сутки после разовой покупки на $10); модели с суффиксом `:free` | openrouter.ai/keys | `https://openrouter.ai/api/v1` |
| **Google Gemini** — самый сильный из бесплатных | бесплатный тариф в AI Studio, без карты; **данные могут использоваться для обучения** (вне ЕС/Великобритании/Швейцарии) | aistudio.google.com/apikey | `https://generativelanguage.googleapis.com/v1beta/openai/` |
| **Cloudflare Workers AI** | 10 000 «нейронов» в сутки | dash.cloudflare.com → Workers AI → API Tokens | `https://api.cloudflare.com/client/v4/accounts/<account_id>/ai/v1` |
| **Z.ai (GLM)** | бесплатные Flash-модели, ~1 000 запросов/сутки | z.ai | их OpenAI-совместимый эндпоинт |
| **Ollama на своей машине** | без лимитов вообще, нужна только оперативная память | — | `LOCAL_*` (см. п. 1.5) |

Что важно для этого проекта: **одно сообщение клиента — это два вызова модели** (разбор запроса
и формулировка ответа), поэтому суточный лимит в запросах делите на два. Groq с 1 000/сутки —
это ~500 диалоговых сообщений в день, у OpenRouter на free-тарифе 50/сутки — ~20–25 сообщений,
поэтому он годится для демонстрации, а не для целого дня работы. Если лимит исчерпан, движок не
падает: 429 уходит по цепочке, отвечает mock и клиент всё равно получает ответ.

Пример для Groq (ключ из консоли Groq):

```dotenv
LLM_API_BASE_URL=https://api.groq.com/openai/v1
LLM_API_KEY=gsk_...
LLM_API_MODEL=openai/gpt-oss-120b     # имя модели целиком, с префиксом вендора
LLM_TIMEOUT_S=6
```

Пример для OpenRouter (суффикс `:free` в имени модели обязателен):

```dotenv
LLM_API_BASE_URL=https://openrouter.ai/api/v1
LLM_API_KEY=sk-or-v1-...
LLM_API_MODEL=nvidia/nemotron-3-super-120b-a12b:free
```

Проверка — одна команда, она же покажет задержку и понятную ошибку:

```powershell
python scripts\llm_check.py --provider api
```

### GigaChat (Сбер)

```dotenv
GIGACHAT_CREDENTIALS=<ключ авторизации>
GIGACHAT_SCOPE=GIGACHAT_API_PERS     # PERS — физлица, B2B — юрлица (предоплата), CORP — юрлица (постоплата)
GIGACHAT_MODEL=GigaChat-2            # GigaChat-2 | GigaChat-2-Pro | GigaChat-2-Max
GIGACHAT_VERIFY_SSL=false            # true — проверка TLS включена (см. п. 3)
GIGACHAT_CA_BUNDLE_FILE=             # путь к корневому сертификату НУЦ Минцифры
GIGACHAT_MAX_TOKENS=0                # 0 — лимит модели по умолчанию
```

Где взять ключ: личный кабинет [GigaChat API](https://developers.sber.ru/studio) → создать проект →
**«Ключ авторизации»** (это и есть `GIGACHAT_CREDENTIALS`). Scope выбирается при создании ключа:
если в кабинете проект для юрлиц, укажите `GIGACHAT_API_B2B`/`GIGACHAT_API_CORP` — иначе будет 401.
Список доступных аккаунту моделей покажет `client.get_models()` (наш `scripts/llm_check.py`
подставляет модель из настроек и сообщит, если она недоступна: «403 — ключу недоступна модель»).

### YandexGPT (Yandex Cloud)

```dotenv
YANDEX_API_KEY=<API-ключ сервисного аккаунта>
YANDEX_IAM_TOKEN=                     # альтернатива ключу; живёт 12 часов
YANDEX_FOLDER_ID=<идентификатор каталога>
YANDEX_MODEL=yandexgpt-5-lite         # yandexgpt-5-lite | yandexgpt-5-pro | yandexgpt-5.1
YANDEX_MODEL_URI=                     # полный gpt://<каталог>/<модель>; приоритетнее YANDEX_MODEL
YANDEX_MAX_TOKENS=800
YANDEX_REASONING_MODE=                # пусто — для 5-pro/5-lite рассуждения выключены
```

### Как это выглядит в консоли Yandex Cloud (по шагам)

1. **Аккаунт и платёжный аккаунт.** [console.yandex.cloud](https://console.yandex.cloud) → создать облако →
   привязать платёжный аккаунт (без него API не работает). Новым пользователям дают стартовый грант
   (4000 ₽ для физлиц, 10 000 ₽ для юрлиц) — этого хватает на отладку демо.
2. **Каталог (folder).** Создайте каталог; его идентификатор виден в «Дашборде каталога» рядом с
   именем. Это `YANDEX_FOLDER_ID`. Роль и ключ выдаются **на конкретный каталог** — не перепутайте
   каталоги в облаке, где их несколько.
3. **Сервисный аккаунт.** В каталоге → вкладка **«Сервисные аккаунты»** → **«Создать сервисный
   аккаунт»** → имя → **«Добавить роль»** → `ai.languageModels.user` (именно на этот каталог).
   Без роли любой запрос вернёт 403.
4. **API-ключ.** Откройте сервисный аккаунт → **«Создать новый ключ» → «Создать API-ключ»** →
   в **«Области действия»** укажите `yc.ai.languageModels.execute` (узкий scope, а не «доступ ко
   всему») → при желании задайте срок действия → **«Создать»**. Секрет показывается **один раз** —
   это `YANDEX_API_KEY`.
5. **Настройки движка** — три строки в `.env` (см. блок выше) и `python scripts\llm_check.py
   --provider yandex`. Скрипт напечатает задержку и ответ модели либо подсказку, чего не хватает.
6. **IAM-токен вместо ключа (необязательно).** `yc iam create-token` → `YANDEX_IAM_TOKEN`; живёт
   12 часов и требует обновления, поэтому для сервиса удобнее API-ключ, а токен — для разовых проверок.

## 1.5. Бесплатный вариант: локальная модель с открытыми весами

Платить не обязательно: у российских моделей открыты веса под свободными лицензиями, и их можно
поднять на своей машине — тогда работает тот же провайдер `local`, а данные не покидают контур.

| Модель | Лицензия | Вес (Q4) | Где взять |
|---|---|---|---|
| **GigaChat-20B-A3B-instruct v1.5** (Сбер) | MIT, можно коммерчески | ≈12,5 ГБ | `ollama run hf.co/ai-sage/GigaChat-20B-A3B-instruct-v1.5-GGUF:Q4_K_M` |
| **GigaChat 3 Lightning 10B-A1.8B** (Сбер) | MIT | ≈7 ГБ | `ollama pull forzer/GigaChat3-10B-A1.8B` — легче и быстрее 20B |
| **YandexGPT-5-Lite-8B-Instruct** (Яндекс) | YandexGPT-5-Lite-8B | ≈5 ГБ | Hugging Face: `yandex/YandexGPT-5-Lite-8B-instruct` (есть GGUF-сборки) |
| Qwen3 / GPT-OSS / DeepSeek-R1-Distill | Apache 2.0 | 4–12 ГБ | запасной вариант, если нужна модель «покрепче» на том же железе |

Что нужно от железа: 8 ГБ оперативной памяти хватает 8B-модели в Q4 (пойдёт медленно, но пойдёт),
12–16 ГБ + GPU — для 20B в Q4_K_M. Генерация на CPU ≈2–6 токенов/с, то есть ответ придёт за
несколько секунд: для демо это нормально, но `LLM_TIMEOUT_S` поднимите до 20–30 с.

```powershell
# 1. Ставим сервер: Ollama (Windows/macOS/Linux) — https://ollama.com/download
ollama pull forzer/GigaChat3-10B-A1.8B          # или 20B: hf.co/ai-sage/GigaChat-20B-A3B-instruct-v1.5-GGUF:Q4_K_M
ollama list                                      # проверить, что модель скачалась

# 2. Прописываем в .env (Ollama отдаёт OpenAI-совместимый API на порту 11434)
#    LLM_PROVIDER=local           # свои веса: без внешних вызовов; auto — API/GigaChat → local → mock
#    LOCAL_MODEL=forzer/GigaChat3-10B-A1.8B
#    LOCAL_BASE_URL=http://127.0.0.1:11434/v1
#    LLM_TIMEOUT_S=25             # CPU-инференс медленный: даём бюджет

# 3. Проверяем
python scripts\llm_check.py --provider local
```

LM Studio, `llama-server` из llama.cpp и vLLM подходят так же — у всех один и тот же протокол:
`LOCAL_BASE_URL=http://127.0.0.1:1234/v1` (LM Studio), `http://127.0.0.1:8080/v1` (llama.cpp).
Если сервер требует токен (например, шлюз на несколько машин) — `LOCAL_API_KEY`.

Плюсы локального контура: 0 ₽, нет лимитов и квот, персональные данные не уходят в облако
(152-ФЗ), работает без интернета. Минусы: качество формулировок у 8–20B ниже облачного GigaChat,
скорость на CPU заметно ниже, модель нужно скачать (5–13 ГБ) и держать сервер запущенным.
Для защиты проекта этого достаточно: числа и решения по-прежнему считает код, модель только
переписывает факты в текст.

**Бесплатные квоты облака** тоже есть, но с оговорками: у Yandex Cloud — стартовый грант
(4000 ₽ физлицам, 10 000 ₽ юрлицам), у GigaChat — бесплатный доступ для физлиц в веб-интерфейсе;
условия меняются, поэтому перед демо проверьте их в личных кабинетах. Зарубежные бесплатные
тарифы (Gemini, Groq и т.п.) для этого проекта не подходят: доступ из РФ нестабилен, а персональные
данные клиентов уйдут за границу — это прямое нарушение наших же правил по ПДн.

## 2. Установка SDK и запуск

```powershell
pip install -r requirements.txt          # ядро движка
pip install -r requirements-llm.txt      # GigaChat SDK (YandexGPT работает без пакетов)
```

В Docker SDK ставится флагом сборки (переменные LLM приходят из `.env` через `env_file`):

```powershell
$env:WITH_LLM="1"; docker compose up --build
```

## 3. Сертификат НУЦ Минцифры (для GigaChat)

GigaChat API отвечает сертификатом, выпущенным Минцифры; Python-клиенты используют свой
набор корневых сертификатов (`certifi`), поэтому проверка TLS падает с
`CERTIFICATE_VERIFY_FAILED`. Правильное решение — скачать «Russian Trusted Root CA» с
[gosuslugi.ru/crt](https://www.gosuslugi.ru/crt) и указать файл:

```dotenv
GIGACHAT_CA_BUNDLE_FILE=C:\certs\Russian Trusted Root CA.cer
GIGACHAT_VERIFY_SSL=true
```

`GIGACHAT_VERIFY_SSL=false` (значение по умолчанию в примере) — только для локальной отладки:
трафик с клиентскими данными без проверки сертификата доверять нельзя.

## 4. Проверка за минуту

```powershell
python scripts\llm_check.py            # опросит все провайдеры с ключами
python scripts\llm_check.py --provider yandex --json
```

Скрипт делает те же два вызова, что и движок (JSON-классификация и генерация текста),
печатает время ответа, а ошибки — с подсказкой по настройке. Состояние LLM видно и снаружи:

```powershell
curl http://localhost:8000/api/health     # {"provider":"gigachat→yandex→mock", "llm_ready":{...}, "llm_missing":{...}}
```

`llm_missing` перечисляет **имена** незаданных переменных (значения ключей нигде не отдаются),
поэтому health можно смотреть без опаски. Сайт коллег показывает то же самое через
`/api/site/health`.

## 5. Бюджет времени и поведение при сбоях

* `LLM_TIMEOUT_S` (по умолчанию 2.5 с) — сколько всего времени даётся на попытку получить ответ.
  Облачные модели отвечают за 0,5–2 с; если сеть медленная, поднимите значение до 4–6 с.
  Дольше ждать нет смысла: клиент в чате уже получил «я уточняю» — это делает движок, а не модель.
* Таймаут обеспечивает сама цепочка (`FallbackChain`), а не SDK: у GigaChat SDK свой таймаут
  запроса выставляется в его же величину, чтобы не пересиживать бюджет.
* Ошибка провайдера (401/403/429/сеть/невалидный JSON) не всплывает к клиенту: в трассе
  появляется событие `llm_error`, ответ формирует следующий провайдер, в худшем случае mock.
* Разные ошибки намеренно разделены, чтобы диагностика была быстрой: невалидная структура
  ответа — `LLMInvalidResponse` (движок повторит запрос), недоступность — `LLMError`/`LLMTimeout`
  (движок сразу уходит по цепочке).

## 6. Если не работает

| Симптом | Причина и что делать |
|---|---|
| `mock` в `/api/health`, хотя ключи заданы | ключи не подхватились: `.env` читается из корня проекта; проверьте `llm_missing` и `scripts/llm_check.py` |
| `api: 401 — ключ не принят` | ключ чужого шлюза или скопирован с переносами строк; проверьте `LLM_API_KEY` для того адреса, что стоит в `LLM_API_BASE_URL` |
| `403 … error code: 1010` | отклонила защита Cloudflare, а не провайдер: так бывает от клиента без `User-Agent` (stdlib шлёт `Python-urllib`). В этой версии клиент представляется сам (`LOS-CRM/1.0`), но если вы правили запрос — вернуть заголовок |
| `api: 402 — на счету нет средств` | у OpenRouter/DeepSeek нулевой баланс: пополните или смените модель (402 приходит вместо 401) |
| `api: 404 — модель недоступна` | имя модели у шлюза своё: у OpenRouter это `vendor/model`, у Groq — свой список; сверьте `LLM_API_MODEL` |
| `api: 429 — лимит запросов` | бесплатный тариф исчерпан (у OpenRouter это всего 50 запросов/сутки): подождите сброса, смените модель — или пусть отвечает mock, он никуда не делся |
| `response_format` отвергнут (400) | шлюз не умеет строгий JSON: `LLM_JSON_MODE=false` — JSON всё равно разбирается из текста |
| `401 — проверьте GIGACHAT_CREDENTIALS` | ключ авторизации неверен или отозван; проверьте также `GIGACHAT_SCOPE` (PERS/B2B/CORP) |
| `403 — ключу недоступна модель` | у ключа нет доступа к `GIGACHAT_MODEL`; возьмите модель из `client.get_models()` |
| `CERTIFICATE_VERIFY_FAILED` | не установлен корневой сертификат НУЦ (см. п. 3) |
| `403 — нет роли ai.languageModels.user` | роль не выдана сервисному аккаунту **на этот каталог** |
| `400 — проверьте YANDEX_MODEL, YANDEX_FOLDER_ID` | устаревший идентификатор модели или чужой каталог в `modelUri` |
| `429 — исчерпана квота` | лимиты тарифа (у YandexGPT — 10 синхронных генераций на каталог); подождите или запросите увеличение квоты в поддержке |
| YandexGPT отвечает, но медленно (>2,5 с) | поднимите `LLM_TIMEOUT_S` до 4–6 и проверьте `llm` в `/api/health`: возможно, запрос уже уходит в mock |
| Запрос уходит в чужой каталог | `YANDEX_FOLDER_ID` и роль выданы на разные каталоги — сверьте оба |
| `SDK gigachat не установлен` | `pip install -r requirements-llm.txt` (или `WITH_LLM=1` для Docker) |
| `local: сервер не отвечает` | не запущен Ollama/LM Studio: `ollama serve`, проверьте `LOCAL_BASE_URL` |
| `local: модель не найдена (404)` | скачайте её: `ollama pull <модель>`, сверьте `LOCAL_MODEL` со `ollama list` |
| Локальная модель отвечает через 10–30 с | это норма для CPU: поднимите `LLM_TIMEOUT_S` до 25–30 |
| Ответы «слишком общие» | модель не успевает в `LLM_TIMEOUT_S`: увеличьте бюджет и проверьте `llm` в метриках |
| Клиент получает ответ mock при живых ключах | смотрите логи API (`LLM provider … failed`) — там имя исключения провайдера |

## 7. Как это устроено внутри (коротко)

* `core/llm/base.py` — общий интерфейс (`complete_json`/`complete_text`), ошибки, извлечение JSON
  из ответа (модели любят добавлять пояснения и ```-ограждения), `default_timeout()` из настроек.
* `core/llm/gigachat.py` — официальный SDK: он сам держит OAuth-токен и обновляет его.
  Поддержаны оба контракта SDK: `client.chat(payload)` (0.1.x и совместимый шим 0.2.x) и
  `client.chat.create(...)` (0.2.x), ответ читается в обоих форматах.
* `core/llm/yandex.py` — REST через stdlib: `POST /foundationModels/v1/completion`, авторизация
  `Api-Key`/`Bearer`, `modelUri` из каталога и модели.
* `core/llm/openai_compat.py` — общий код для любого OpenAI-совместимого чата: payload,
  разбор `choices[0].message.content`, превращение 401/402/403/404/429 в подсказки, JSON-режим.
  Клиент отправляет `User-Agent`, иначе облачные API за Cloudflare отвечают `403 error code: 1010`
  раньше, чем проверят ключ (проверено на Groq: без подписи — 403, с подписью — честные 401/200).
* `core/llm/api.py` — «любая API-модель»: облачный эндпоинт из `LLM_API_*`, стоят первым в `auto`.
* `core/llm/local.py` — тот же протокол, но на своей машине (Ollama, LM Studio, llama.cpp, vLLM):
  бесплатный контур с открытыми весами, данные не покидают контур.
* `core/llm/__init__.py` — сборка цепочки по `LLM_PROVIDER`, общий бюджет времени, сводка для
  health (`describe_llm`, `provider_status`).
* `scripts/llm_check.py` — диагностика: ключи, задержка, понятная ошибка.

Тесты — `tests/test_llm_providers.py`: проверки без сети и без ключей (подменяются SDK и `urllib`) —
формат запроса, разбор ответов обоих контрактов GigaChat, подсказки на 401/402/403/404/429,
порядок цепочки с любым API-провайдером и переход на mock при недоступной сети.
