# ЛОСЬ — AI-native CRM (хакатон-MVP)

Фронтенд-демо AI-native CRM по ТЗ v5: чат клиента, дашборд менеджера, Policy Management,
безопасность и метрики. Поверх REST-API работает детерминированный mock-движок (аналог `MockLLM`
из roadmap), поэтому **всё демо работает без внешних LLM-ключей и без БД**.

> Принцип надёжности из плана: «LLM говорит — код решает». Числа, скидки и SLA рождаются
> только в детерминированном коде поверх версионируемой Policy Matrix.

## Быстрый старт локально (5 минут)

Требуется только **Node.js 20+**.

```bash
npm install          # один раз
npm run build        # production-сборка
npm start            # → http://localhost:3000
```

Режим разработки с hot-reload:

```bash
npm run dev          # → http://localhost:3000
```

Postgres и `.env` **не обязательны**: демо-хранилище — в памяти процесса.
Для персистентности скопируйте `.env.example` → `.env` и укажите `DATABASE_URL`.

## Запуск в Docker (self-hosting)

```bash
docker compose up --build     # → http://localhost:3000
docker compose down
```

Профиль с Postgres (для персистентности):

```bash
DATABASE_URL=postgresql://postgres:postgres@db:5432/app_db docker compose --profile db up --build
```

## Вход и роли

Рабочая часть сайта доступна только сотрудникам: страницы и API без сессии уводят на `/login`
(передний контур — `src/proxy.ts`), а сам вход проверяет пароль на бэкенде — PBKDF2-хеши
живут только там и в интерфейс не попадают.

| Роль | Что доступно |
|---|---|
| **менеджер** | диалоги, дашборд, уведомления, метрики и инциденты; может переопределить любое авто-решение (Ст. 5) |
| **администратор** | то же плюс Policy Matrix (просмотр и редакция) и раздел «Сотрудники» |

Администратор создаёт новых сотрудников в `/team`: логин, пароль и роль. Смена пароля, роли
и отключение учётки сразу гасят активные сессии этого сотрудника; нельзя убрать роль
администратора у себя или у последнего администратора — система не останется без доступа.

Демо-доступ первого запуска: `admin / admin` (администратор), `manager / manager` (менеджер).
Пароли по умолчанию переопределяются переменными `ADMIN_PASSWORD` и `MANAGER_PASSWORD` на бэкенде.
Если бэкенд выключен, сайт работает на демо-движке (`engine: "mock-fallback"`) и **права проверяет
сам** — менеджер в этом режиме тоже получает 403 на Policy Matrix, симуляторе и сбросе демо-данных;
учётки хранятся в памяти процесса (`__LOS_USERS__`) до перезапуска.

## Мост к реальному backend (FastAPI + SQLite)

UI — тонкий клиент, поэтому подключение настоящего пайплайна не потребовало изменений интерфейса:
каждый `src/app/api/**/route.ts` сначала спрашивает backend, а если тот не задан или недоступен —
отдаёт прежний ответ встроенного демо-движка. Автономность демо при этом сохраняется.

```
браузер → /api/… (Next-сервер) → CRM_BACKEND_URL/api/site/… (FastAPI)
                    └── backend не ответил → src/server/store.ts (mock-фоллбек)
```

1. Поднять backend: `uvicorn app.main:app --port 8030` (папка `ai-native-srm`).
2. Задать `CRM_BACKEND_URL=http://127.0.0.1:8030` (см. `.env.example`) и перезапустить dev-сервер.
3. Проверить `/api/health`: `"engine": "backend"` — данные идут из FastAPI, `"mock-fallback"` — сайт на встроенном движке.

Мост серверный, а не браузерный: адрес backend не попадает в клиентский бандл, CORS не требуется,
а три запроса мимо `src/lib/api.ts` (уведомления, политика, сброс демо) тоже проходят через прокси.
Перевод контрактов (camelCase, `dlg-0001`, Policy с `work_hours.from/to`, метрики) живёт в backend
(`app/adapters/site.py`, `app/routers/ui_bridge.py`) — интерфейс не переписывался.
Список клиентов на странице чата тоже приходит с backend (`/api/clients`), поэтому интерфейс
и движок видят одних и тех же клиентов; статический `CLIENT_OPTIONS` остался резервом.

### Проверка моста за минуту

```bash
curl -s localhost:3000/api/health                      # "engine":"backend" — отвечает FastAPI
curl -s localhost:3000/api/clients                     # 6 клиентов из справочника backend
curl -s -X POST localhost:3000/api/messages -H 'Content-Type: application/json' \
  -d '{"client_id":"C-1006","channel":"web","text":"Нужно 10 принтеров LP-220. Какую скидку дадите?"}'
# → «скидка 8%» считается Policy Matrix backend (тир 5% + лояльность 3%), а не локальным policy.ts
```

Остановите backend и повторите запросы: `/api/health` вернёт `"engine":"mock-fallback"`,
а сайт продолжит работать на встроенном демо-движке (41 диалог истории) — демо не зависит
от того, поднят ли FastAPI.

## Демо-сценарии (кнопки на странице чата)

1. **Справка (A)** — цена/наличие из каталога.
2. **Скидка (C)** — расчёт по Policy Matrix; продолжите «А 40%?» → предложение максимума → «Это неприемлемо» → эскалация.
3. **КП (D)** — коммерческое предложение по шаблону «Офис на 20 человек».
4. **Гарантия (G)** — замена за 24 ч по заказу из истории клиента.
5. **Спор (I)** — ACK <100 мс (pre-classifier) → HOLD → уведомление менеджеру на дашборде.
6. **Инъекция (F)** — детерминированный скрипт + инцидент безопасности; легитимная часть вопроса всё равно получает ответ.

Эффектный момент для защиты: на `/policy` нажмите «max_pct → 10%», сохраните,
и повторите сценарий «Скидка» — ответ ИИ изменится **без перезапуска** (политика читается на каждый запрос).

Кнопка «Сбросить демо-данные» в сайдбаре возвращает исходное состояние (41 диалог истории,
живой HOLD АО «НордБанк», актуальная версия политики).

## Архитектура

```
┌ UI (Next.js, App Router) ── тонкий клиент, бизнес-логики нет
│     /api/*  REST-контракт по таблице из roadmap шага 5
├ src/server/engine.ts   оркестратор: perception → understanding → decision → action → learning
├ src/server/store.ts    in-memory демо-стор + сид (фоллбек, когда backend недоступен)
├ src/server/backend.ts  прокси в FastAPI: backend первым, mock — страховкой
├ src/server/templates.ts детерминированные шаблоны (F, ACK-спор, лимит скидки) — без LLM
├ src/lib/policy.ts      calcAllowedDiscount / calcDeliveryCompensation / getManagerSla
└ src/lib/privacy.ts     mask_pii (Ст. 4): телефоны, email, ФИО, серийники, суммы
```

Backend (FastAPI + SQLite) — источник истины: диалоги, решения, политика, заказы, метрики и
инциденты считаются там, а сайт показывает их через прокси. Адрес задаётся `CRM_BACKEND_URL`
(серверная переменная, не `NEXT_PUBLIC_*`): фронтенду не нужны ни CORS, ни знание внутренних ручек.
